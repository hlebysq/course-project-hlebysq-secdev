# ADR-001 — Input Validation & Sanitization

**Status:** Accepted
**Date:** 2025-10-31
**Owner:** @owner

## Context

В текущей версии приложения (v0.2.0) валидация входных данных ограничена базовой проверкой длины заголовка (1–200 символов). Threat Model выявил риски, связанные с вредоносным вводом и утечкой подробной информации об ошибках (R3, R4). Без более строгой валидации возможны XSS-атаки, SSRF, path traversal и DoS через большие payload'ы.

## Decision

Ввести многоуровневую валидацию и санитизацию входных данных:

1. **Санитизация строковых полей**
   - Удаление ведущих/замыкающих пробелов
   - Нормализация Unicode (NFC)
   - Удаление null-байтов и управляющих символов (кроме `\n`, `\r`, `\t`)

2. **Проверка на опасные шаблоны**
   - Запрет шаблонов, приводящих к XSS (`<script`, `javascript:`, `onerror=`, `onload=`, `<iframe`, `<embed`, `<object`)
   - Выдача RFC 7807 ошибки `validation_error` (статус 422) при обнаружении

3. **Валидация URL (SSRF protection)**
   - Разрешать только схемы `http` и `https`
   - Запрет `localhost`, `127.0.0.1`, `0.0.0.0`, `::1`
   - Базовая проверка private IP ranges (10/8, 192.168/16, 172/16)
   - Максимальная длина URL: 2048
   - Запрет `..` и `~` в пути (path traversal)

4. **Ограничения размера запроса**
   - Максимальный размер JSON body: 100 KB (рекомендуется конфигурировать через env)
   - Максимальное количество полей: 50

5. **Rate limiting на уровень ресурса**
   - Лимит записей на пользователя/аккаунт: 1000

Санитизация выполняется до Pydantic-валидации, а отклонённые попытки логируются для аудита.

## Consequences

**Положительные:**
- Существенное снижение риска R3 (инъекции/вредный ввод) и R4 (утечка деталей ошибок).
- Соответствие NFR-002 (все нарушения → 422 `validation_error`).
- Защита от ряда SSRF-векторов и XSS.

**Отрицательные:**
- Увеличение объёма кода и времени обработки (порядка ~5–10 ms) на валидацию.
- Возможны false-positives, требующие донастройки списков шаблонов.

**Технический долг / дополнительные работы:**
- Добавить конфиг лимитов через env vars.
- Рассмотреть интеграцию с более продвинутой библиотекой для очистки HTML (например, `bleach`) при необходимости.
