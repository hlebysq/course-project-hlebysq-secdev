# ADR-003 — Client Policies: таймауты, лимиты и ретраи для исходящих HTTP-запросов

**Status:** Accepted
**Date:** 2025-11-01
**Owner:** @owner

## Context

Сейчас в сервисе не реализовано взаимодействие с внешними ресурсами, но в дальнейшем оно планируется, поэтому принято решение задокументировать это заранее. Без ограничений исходящие запросы создают риски:

- **R10 — SSRF / доступ к приватным сетям** (вызовы на внутренние адреса).
- **R11 — DoS через медленные/неограниченные ответы** (блокировка потоков, переполнение памяти при больших ответах).
- **R12 — Нестабильность из-за transient ошибок внешних сервисов** (отсутствие ретраев или неправильные retry-политики).

Связанные NFR: NFR-003 (Performance), NFR-002 (Validation).
Связанная функциональность: внешние HTTP-клиенты, интеграции.

## Decision

Ввести каноничную политику для всех исходящих HTTP-вызовов (Client Policies):

1. **Таймауты:**
   - Connect timeout (по умолчанию 5s)
   - Read timeout (по умолчанию 5s)
   - Конфигурируемо через `OUTGOING_TIMEOUT_CONNECT`, `OUTGOING_TIMEOUT_READ`

2. **Ограничение количества соединений:**
   - `OUTGOING_MAX_CONN` (по умолчанию 10)
   - `max_keepalive_connections` (по умолчанию 5)

3. **Ограничение размера ответа:**
   - Максимально считываемый payload (по умолчанию 1 MB) — `OUTGOING_MAX_RESPONSE_BYTES`.

4. **Retry-политика:**
   - `OUTGOING_MAX_RETRIES` (по умолчанию 2) retries для transient ошибок (timeouts, connect errors) с экспоненциальным backoff.
   - Ретраи применяются только для классифицированных transient ошибок; для других ошибок немедленно возвращать проблему upstream.

5. **Повторное использование SSRF-проверок:**
   - Перед отправкой исходящих запросов прогоняем URL через ту же функцию `validate_url_safety` (ADR-001).

6. **Клиент как singleton:**
   - Создаём и кэшируем один экземпляр http client (`app.state.http_client`) с конфигурацией выше.

7. **Ошибки:**
   - При проблемах возвращаем RFC 7807 ошибку с корректным `type`/`status` и `correlationId` (ADR-002).

## Consequences

**Положительные:**
- Снижение риска DoS/ресурсных атак со стороны внешних URL.
- Более предсказуемое время отклика при внешних интеграциях (NFR-003).
- Устойчивость к transient ошибкам за счёт ретраев.

**Отрицательные:**
- Неправильная настройка ретраев может увеличить суммарную задержку операций.
- Дополнительная конфигурация и мониторинг параметров.

**Operational:**
- Env vars: `OUTGOING_TIMEOUT_CONNECT`, `OUTGOING_TIMEOUT_READ`, `OUTGOING_MAX_RETRIES`, `OUTGOING_MAX_RESPONSE_BYTES`, `OUTGOING_MAX_CONN`.
- Runbook должен описывать рекомендуемые значения и причинно-следственные сценарии при изменении параметров.

## Tests / Artifacts

- `tests/test_client_policies.py` — unit tests для:
  - позитивного сценария (успешный fetch),
  - retry-логики (timeout → успех),
  - SSRF-блокировки при внутреннем/приватном адресе,
  - поведенческих тестов на слишком большой ответ (fetched content too large).
